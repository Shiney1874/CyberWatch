02 / Awareness & education

Stay safe online.

Clear, practical guidance for you, your family and your small business.

PHISHING PRACTICE

Can you spot the warning signs?

Read each fictional message and choose the safer next step.

Protect your passwords and accounts
  1. Give every account a different password. Protect your main email account first: it often controls password resets elsewhere.
  2. Use a password manager to generate and store long, unique passwords. Never paste a real password into an unfamiliar checking tool.
  3. Turn on two-step verification. Choose passkeys or a security key where available; an authenticator app is another option.
  4. Keep recovery codes somewhere safe, separate from the account they unlock.
Source: NCSC online safety guidance
Spot phishing before it catches you
  1. Pause when a message demands urgent payment, a password or a verification code. A familiar logo or sender name does not prove a message is genuine.
  2. Open the service through its official app or a bookmark instead of a link in an unexpected message.
  3. Verify unusual requests with the sender using a phone number you already trust.
  4. If you entered a password on a suspicious page, change it through the real service and check other accounts where you reused it.
  5. In the UK, forward suspicious emails to report@phishing.gov.uk. Report suspicious texts to 7726.
Source: NCSC phishing guidance
Keep devices updated and data recoverable
  1. Enable automatic updates for your operating system, browser and apps. Replace software that no longer receives security fixes.
  2. Keep device security protection enabled and install apps from trusted sources.
  3. Back up important files regularly. Keep a separate backup that malware cannot easily overwrite.
  4. Test restoring a file so you know your backup works when you need it.
Source: NCSC updates and backup guidance
A starter checklist for small businesses
  1. List the devices, accounts and important data your business relies on.
  2. Use individual staff accounts, two-step verification and the minimum access each person needs.
  3. Keep backups, apply updates and train your team to verify payment changes by a trusted channel.
  4. Write down who to call and what to disconnect if an account or device is compromised.
  5. Remove access promptly when someone leaves.
Source: NCSC small business guide

06 / Network security

Understand and defend your network.

Explore segmentation, review exposed services and investigate network activity from a defender’s perspective.

Security-zone subnet explorer

INTERACTIVE PRACTICE

Use IPv4 ranges to plan separate security zones for staff devices, guest Wi-Fi and servers. Calculate a subnet to understand which addresses a firewall rule would cover.

Security exercise: compare 192.168.1.42/24 with /28. Which range would a rule cover? Subnets alone do not enforce isolation: control traffic between zones with firewall rules, then verify the permitted connections.

Network defence essentials

01 / LIMIT MOVEMENT

Segmentation & least privilege

Separate guest devices, workstations and sensitive servers into security zones. Permit only the connections each zone needs, so one compromised device has fewer routes to other systems.

02 / REDUCE EXPOSURE

Firewalls & remote access

Record why each exposed service is needed. Restrict administrative access to approved paths, require strong authentication, keep systems patched and remove unnecessary services.

03 / INVESTIGATE SIGNALS

DNS, TLS & network evidence

Compare DNS queries, connection logs and certificate details with expected activity. Unfamiliar destinations or repeated failures deserve context; a single unusual event does not prove compromise.

Review a firewall rule before allowing traffic
  1. Identify the business purpose, owner and systems that need the connection.
  2. Specify the narrowest appropriate source, destination, protocol and port. Avoid broad access when a specific rule will work.
  3. Check authentication and encryption for the actual service; an allowed port is not a security guarantee.
  4. In an authorised lab, test both a connection that should succeed and one that should be denied.
  5. Record the outcome, review date and rollback steps. Check logs after the change.

This is a learning checklist. The explorer does not change any firewall settings.

OWASP network segmentation guidance
Investigate an unexpected outbound connection
  1. Record the timestamp, source device, destination, port and available process information.
  2. Compare the destination with expected applications, DNS records and approved services.
  3. Check related authentication, endpoint and firewall events. Consider updates, retries and shared infrastructure before drawing conclusions.
  4. Preserve relevant evidence and follow your organisation’s incident-response process if the activity remains suspicious.

Practise with fictional logs or traffic captured in a lab you are authorised to inspect.

Secure coding essentials
01 / DEFENSIVE AUTOMATION
Parse events without leaking secrets
Use Python to summarise failures and correlate timestamps. Handle missing fields and avoid writing passwords, tokens or sensitive personal data into logs.
OWASP security logging guidance
02 / UNTRUSTED INPUT
Prevent injection & XSS
Validate inputs on the server, use parameterised database queries and display untrusted text with safe APIs such as textContent. Choose protections appropriate to the output context.
OWASP DOM XSS prevention
03 / SECRETS & DEPENDENCIES
Protect keys and review changes
Keep credentials out of code and public repositories. Use a suitable secret store, rotate exposed keys and review dependency updates before releasing changes.
OWASP secrets management


Build safer programming habits from day one
  • Validate inputs and handle unexpected values and errors.
  • Keep secrets such as passwords and API keys out of source code and public repositories.
  • Use parameterised database queries instead of building queries from untrusted text.
  • Keep dependencies current and understand what a library does before adding it.
  • Test normal cases, invalid inputs and boundary conditions.
Start with a small project you can understand completely, then add one feature at a time.
